# JARVIS Situation Gym

Double-click **JARVIS Situation Gym** on the Windows Desktop or Start menu. This is a packaged native Windows program with its own Python/Tk runtime; it is not a Codex browser session. JARVIS's local chat relay and model must be running.

1. Open **Operator’s context** to add real routines, constraints or a read-only calendar export. The initial PC/phone scenario reflects Operator's JARVIS use case; service details, prices and the default appointment are fictional. No real appointments have been imported yet.
2. Select a situation and variation seed, then **Start a run**.
3. Watch the actual JARVIS decisions, simulated tool outcomes, NPC changes and process score. **Stop after this turn** preserves the trace. Closing a running app requests a clean stop after the current answer.
4. At the end, JARVIS reviews his trace and proposes a lesson. Check **Real PSC imprint**; a failed or rejected imprint is not reported as learning success.
5. Open **Runs & Astra reviews** for full records and daily findings.

## What is real, and what is simulated

The actual `/chat` service, MindLoop, front-brain reasoning/model call, intent classifier, Judge, and append-only PSC are used. The simulation supplies an environment and restricts the available tool schema, then dispatches approved actions to local fixtures. Calendar reads, service searches, reservations, failures, and changes of plan occur only inside that world. No real purchase, booking, message, internet research, or code change is performed by a scenario tool.

NPC utterances use conversational language. Structured arguments and receipts remain in the full trace. Scores reward clarification, source checking, tool order, recovery, changed requirements, verification and improvement proposals—not statements that the task is complete. Language scoring is a limited heuristic; Astra's review checks actual semantics and unsupported claims.

Normal simulation turns suppress personal-fact ingestion. JARVIS's generated review is labeled **SIMULATION LESSON**, and the existing Judge decides whether it can be appended to his real PSC. Stored lessons are available to the existing live memory/context system. Storage alone does not prove transfer or improved general intelligence.

## Daily Astra job

The review is scheduled for **9 PM Eastern every day**. Astra reads new/changed traces, reproduces failures with bounded local tests, and proposes specific fixes. It writes a dated report and gives Operator one findings summary; no new runs means no notification. The Astra job requires the Codex host to be available. It does not deploy changes, change voice/core/Judge/permissions, or carry out real errands.
